3 · Inside the code

    
Every request to either server goes down the same stack of layers. Each layer has one job, which is why a feature always splits into the same four files.

  

  

  

    

      
Shop API

      
backend/ · Render · port 4000


src/
  server.js       # starts HTTP + the minute job
  app.js          # middleware + every router
  config/env.js   # checks .env at startup
  lib/            # prisma, stripe, email,
                  # cloudinary, rate limiter
  middleware/     # auth, validate, errors
  jobs/           # cancel unpaid orders
  modules/
    auth  catalog  cart  wishlist
    coupons  orders  payments
    webhooks  reviews  profile
    invoices
    admin/  products orders
            customers analytics

6 · Where it runs

    
Everything is on free plans. Servers and databases sleep when idle, so the first visit after a quiet spell is slow; every layer is built to wait or retry instead of failing.

7 · Run it locally

    
One terminal for the four apps; a second only when testing payments.

  

  

    
Start everything
project root


npm run install:all   # first time only
npm run dev           # api :4000  cms :4100
                      # store :5173  admin :5174

    
Payments locally
second terminal


stripe listen --forward-to \
  localhost:4000/api/webhooks/stripe
# test card 4242 4242 4242 4242

    
Database changes
backend/ or cms/


npm run db:migrate    # new migration (dev DB)
npm run db:studio     # browse tables
npm test              # 58 tests (test DB)
